3-Day Individual Hackathon: Retail The Intelligent Retail Shopping Assistant: From Product Search to Order Fulfillment The user A retail customer who wants to quickly find the right product, understand availability and offers, complete a purchase, and track the order. A retail store manager who needs visibility into orders, inventory issues, and items that require attention. The pain Online retail customers may search using very different language from the actual product catalogue. For example: "Black office shoes below ₹4,000" "Comfortable formal shoe" "Work shoes black size 9" "Formal footwear under 4k" Even when the right product is found, customers still need to understand whether it is available, what alternatives exist, whether an offer applies, and when they can receive it. On the retailer side, inventory availability and order exceptions may exist in separate views, making it difficult to identify which products or orders need immediate attention. The challenge is to create a small but complete intelligent retail application connecting the customer shopping journey to basic retail operations. What done looks like Build a browser-based retail application using synthetic data that demonstrates the following end-to-end journey.
Intelligent Product Search Provide a catalogue of approximately 50-100 synthetic products across 3-5 categories. The customer can search naturally: "Black running shoes below ₹5,000" The solution should understand: Product/category Price range Colour Basic product attributes and return relevant products. It should also handle reasonable variations such as: "running shoe black" "black sports shoes" "shoe for running below 5k" Expected demo Show two or three differently worded searches returning sensible products from the same catalogue.
Product Recommendation When a customer selects a product, show: Product details Price Available variants Stock availability Similar products One or two complementary products The application should explain its recommendation. For example: Recommended alternative: Similar running category and price range, with your requested size currently available. This does not need a complex recommendation model. An explainable rule-based, similarity-based, or AI-assisted approach is acceptable.
Inventory Availability Maintain synthetic inventory across three stores and one warehouse. For the selected item show: Available Low stock Out of stock Available at another location Example: Size 9 Hyderabad Store: 2 Bengaluru Store: 0 Chennai Store: 4 Warehouse: 12 If the selected location is unavailable, recommend a sensible alternative.
Cart & Promotion Customer should be able to: Add product Remove product Change quantity See price Apply one or more predefined offers See discount See final amount Example: RETAIL10 10% discount for eligible orders above ₹3,000. The application should explain why an offer was accepted or rejected.
Place Order Provide a simple checkout using synthetic customer information. Customer selects: Home delivery or store pickup Delivery/store location Products and quantities Then: Place Order The application creates an order and reserves/reduces the relevant inventory. No real payment gateway is required.
Simple Fulfillment Logic The application should determine where the order should be fulfilled from. Consider only: Stock availability Ability to fulfil the complete order Location Simple fulfillment priority Example: Fulfil from Hyderabad Store Reason: All ordered items are available from the same location and the store is eligible for the selected delivery option. This gives individuals a meaningful logic problem without asking them to build a full supply-chain optimization engine.
Order Tracking After placing the order, provide a simple order journey: Order Placed → Confirmed → Picking → Packed → Dispatched → Delivered Allow the demo to simulate progression through these stages. Show: Order number Products Fulfillment location Current status Expected next stage
Retail Manager View This should be the other side of the same application, not a separate project. Provide a simple dashboard showing: Orders Total orders Open orders Orders awaiting fulfillment Inventory Low-stock products Out-of-stock products Products requiring replenishment Sales Total synthetic sales Top-selling products Sales by category The manager should be able to click a problem and see the underlying products or orders.
AI Retail Assistant Each individual should implement one meaningful AI capability. A manager should be able to ask: "Which products are running low?" "What are my top-selling products?" "Show products that are out of stock." "Which orders are still being fulfilled?" "What should I pay attention to?" The answer should be based on the application's synthetic data. For example: 3 products require attention. Running Shoe X has only 2 units remaining in Hyderabad against 8 units sold recently. Consider replenishing it first. The response should provide the underlying evidence rather than generating a generic recommendation. Mandatory End-to-End Demo I would make this the final assessment scenario for every individual participant: Customer enters search → Finds appropriate product → Reviews product recommendation → Checks inventory → Adds product to cart → Applies promotion → Places order → System selects fulfillment location → Inventory changes → Customer tracks order → Retail manager sees the transaction → Low-stock condition appears → Manager asks the AI assistant: "What inventory needs my attention?" → AI identifies the relevant item and explains why. This gives you a genuine end-to-end retail solution without making the individual build an unrealistic enterprise retail platform. 3-Day Plan for an Individual Day 1: Customer Experience Build: Synthetic data Product catalogue Product search Filters Product detail Recommendation Inventory availability Base UI Checkpoint: Search → Product → Availability must work. Day 2: Commerce & Fulfillment Build: Cart Promotion Checkout Place order Inventory update Fulfillment selection Order tracking Checkpoint: Search → Purchase → Fulfillment must work end to end. Day 3: Retail Intelligence Build: Manager dashboard Low-stock identification Sales/order insights AI retail assistant Explainability UI refinement Testing Final demo Checkpoint: Customer journey + retailer journey + AI must work together.
